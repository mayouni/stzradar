# Week 2026-W45 (November 2 to 8, 2026)

Radar's first week. Seven developments were kept, each read at its source and judged against what Softanza
builds. The common thread: agents are now trusted with real power, so the old questions come back in a new form.
Where do the secrets go, where does a tool come from, where does an action's target come from, and how do we know a
repair is right?

**A coding agent's "don't ask again" writes secrets into a file that gets published** (security, action).
When a Claude Code user approves a command for good, the exact command, password included, is saved in
`.claude/settings.local.json` in the project. Apiiro counted 1,122 public copies on GitHub holding a real secret.
Softanza's six repositories hold no such secret, and four of them exclude the file in their own `.gitignore`.
We propose the same line for stzlib and Haro, a `.gitignore` line for each, a check for passwords inside commands over agent files, and a house rule:
reference a secret as `$NAME`, never type it.
[Read the entry](../items/2026/2026-11-08-agent-approvals-leak-secrets.md)

**Code repaired by a model after an API change can pass its checks and still be wrong** (paper, advice).
In a careful study over CPython, Node.js and SQLite changes, a gate of typical inputs let 41% of wrong repairs
through, and one input written from the release note cut that to 6.5%. Softanza is moving its library to Haro,
largely by agents, so we propose exactly that gate for port changes, with expected answers read off the old
runtime. [Read the entry](../items/2026/2026-11-08-llm-repairs-pass-wrong.md)

**SPILLWAY: an agent may act only on targets that came from a trusted, typed field** (paper, advice).
A deterministic rule, with no model in it, admits a side effect only when its target came from the user or from a
typed field of a read-only tool. The authors report no in-scope injection succeeding across twelve settings. Softanza
governs agents with rules too; the paper adds a question ours may not ask yet: where did the target come from?
[Read the entry](../items/2026/2026-11-08-spillway-target-admission.md)

**A prompt library ran any function a template named** (security, advice).
banks imported and called whatever a template's tool path named (CVE-2026-61536); the fix resolves tools only from a
registry. We ask stzlib's intelligence plane to check that declarative agents do the same, and to keep a guard proving
it. [Read the entry](../items/2026/2026-11-08-tool-paths-from-prompts-run-code.md)

**Two MCP clients let a malicious server obtain a token meant for another server** (security, advice).
mcp-go and ChatCLI took the resource a server declared without checking it against the server they had connected to.
We propose the check as a requirement for every MCP client Softanza builds: one sentence and one guard.
[Read the entry](../items/2026/2026-11-08-mcp-oauth-resource-check.md)

**Zig 0.17.1 fixes the blockers of 0.17.0** (release, advice).
Softanza's engine builds on Zig 0.15.2, two minor versions behind. We propose measuring an upgrade on a branch, stzlib
first and Haro after, before anyone plans it. [Read the entry](../items/2026/2026-11-08-zig-0-17-1.md)

**GitHub will block pull_request_target in public repositories from December 2** (practice, info).
Trial blocks on November 9 and 16, 16:00 to 18:00 UTC. Softanza's repositories do not use the event; the notice is for
people building public projects with it. [Read the entry](../items/2026/2026-11-08-github-blocks-pull-request-target.md)

## What was looked at and not kept

- Mistral's managed agents and MCP server, Gemini Omni 1.2 Flash's video generation, and Google's cheminformatics
  skills for its agent: real releases, but nothing in them changes what Softanza builds this week.
- Seven other agent-framework advisories (AgentScope, DB-GPT, RAGFlow and others) were seen in the advisory list and
  not opened; none concerns code Softanza uses.
- Papers on code representations for agents, failure prediction for coding agents, signed MCP tools that still leak,
  and repository context for secure code: worth reading, and kept as candidates if a second paper confirms them.
